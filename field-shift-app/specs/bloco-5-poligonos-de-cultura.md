## Problem

Block 4 gives the app a layer registry, one date axis and a basemap adapter that renders nothing. The screen still shows fixture fields on a pale vector basemap, so the user cannot see a real field, cannot see what is behind the polygons and cannot say where the imagery ends and the crop outline begins. Block 5 renders real crop polygons over satellite imagery, gives every class a name and a colour from the region's official legend, and turns a click on a polygon into the selected field of the app.

The product is now centred on United States farms, so the default source set is the United States one. The Crop Sequence Boundaries product of NASS and ERS is the functional equivalent of Trazo3, and it is stronger for this use: one polygon per field per year, keyless, with eight CDL crop codes on the same record. It is not a PMTiles file, so this block keeps the vector tile design and makes the offline per county build an explicit prerequisite. Brazil stays as the second region and keeps the Trazo3 extract, the MapBiomas class table and the Mato Grosso clip.

The risk this spec is written against is a filled polygon that hides the thing the user came to see. The reference application fills at 0.85, which is nearly opaque, because its basemap is a hand drawn pastel map and not imagery. Over a satellite frame the same value destroys the field edges and the planting rows that make the imagery worth the licence. The fill is therefore a named constant with an acceptance test that measures the composited alpha, not a value chosen by eye (R-14, AC-11).

## Game UX rationale

Source: Game UX.md (thumb zone, clear centre, progressive disclosure, peripheral anchoring), as block 3 cites it.

| Control | Wild Rift principle | One line |
|---|---|---|
| Crop polygons | Clear centre | The centre of the screen shows the fields themselves, so the map reads before any panel does. |
| Translucent fill with an outline | Quiet everywhere except the one place you want the eye to go | The fill tints the field and the outline draws its edge; the imagery stays readable underneath, so the eye lands on the boundary the user clicked. |
| Legend (`Polygon` region) | Detail on demand | The legend lists only the classes in view, with the source dataset and year under them, and it sits out of the centre. |
| Class swatch in the readout and in the fields chip | Context on the edge | The selected polygon carries its own colour and name, so the class is legible without opening the legend, including at 360x640 where the region is not mounted. |
| Hover tooltip | Thumb zone | A pointer or a press on a polygon names it where the eye already is. |
| Basemap adapter | Progressive disclosure | EOX is the default and needs no key; the Google adapter is off unless a key exists, so the map never asks for credentials it cannot use. |
| Overview tier | Honest peripheral signal | At low zoom the polygons are merged by class instead of thinning into noise, so what is drawn is still true. |
| Region adapter | One rule, two sources | The same screens serve two countries without a second interface, and the source of every value is a row a judge can read. |

## Requirements

Types follow blocks 2 and 3: ubiquitous, state-driven, event-driven, unwanted behaviour.

### Region adapter

- R-01 (ubiquitous): The app SHALL hold exactly one region adapter interface, `RegionAdapter` in `src/lib/regions.ts`, and exactly two entries in `REGION_ADAPTERS`, `us` (label `United States`) and `br` (label `Brazil`). The active region SHALL be one store value, `regionId`, defaulted to `us` at every width. The region SHALL be chosen by the `?region=` parameter alone (`us` or `br`), SHALL be written to the URL when it is not the default, and SHALL NOT be chosen by a visible selector in this block. An unknown value SHALL leave `us` active. A third region SHALL be one table row plus one adapter entry, with no requirement of this file rewritten.
- R-02 (ubiquitous): Every source specific value SHALL come from Data contracts Tables A to G through the active region adapter, and SHALL NOT be a literal in a component, a store module or a MapLibre style expression. The values are the geometry source and its tier addresses, the id property, the id type and the command prefix, the class source and class table, the class year rule, the area property and unit, the basis label, the readout source string, the licence strings, the fixture ids, the hosting mode and the tile budget. The two regions SHALL share one requirement set, and a value that differs SHALL differ only in the table.
- R-03 (event-driven): A change of `regionId` SHALL clear the polygon selection and the fixture selection, SHALL set the map camera to the region's default view of Table A, SHALL keep the chosen date, the basemap adapter and the layer composition, and SHALL NOT reload the page. It SHALL write `?region=br` when Brazil is active and remove the parameter when the United States is active. After the change, no tile, class table, colour or attribution string of the previous region SHALL be painted or printed.

### Polygon source, tiers and tile budget

- R-04 (ubiquitous): The polygon data SHALL be one MapLibre vector source per tier, added with the `pmtiles` protocol (`addProtocol` from the `pmtiles` package, a dependency that needs its approval line before implementation, OD-08). The detail source SHALL carry the id and class properties named in Table A for the active region, SHALL set `promoteId` to that region's id property, and SHALL declare the `minzoom` and `maxzoom` of R-05. No other vector source SHALL carry crop polygons. The app SHALL read only the properties listed in Table A; it SHALL NOT read the CSB `rgb`, `csbyears`, `inside_x`, `inside_y`, `orig_fid`, `SHAPE__Length` or `SHAPE__Area` fields, and it SHALL NOT read the Trazo3 `hansen_covered_area`, `hansen_loss_area`, `mode_year`, `firstyear`, `firstyearmajority`, the `deforestarea*` columns, `mbcov_area_2024` or `mbvalid_area_2024`.
- R-05 (ubiquitous): The detail tier SHALL have the zoom range in Table B. For the United States the `minzoom` SHALL be read at load from `data/polygons/us-38017.manifest.json`, the build product of CO-B5-01, through the key `detail_minzoom`, and SHALL NOT be a constant in the app. The build SHALL choose the lowest zoom `D` in 6 to 14 at which every detail tile covering the pilot box is at most the R-08 budget, SHALL record `D` as `detail_minzoom`, SHALL record `detail_maxzoom` 14, `overview_minzoom` as `detail_minzoom - 3`, `overview_maxzoom` as `detail_minzoom - 1` and `interactive_minzoom` as `detail_minzoom + 2`, and SHALL fail rather than record a `detail_minzoom` above 9, because the default view is zoom 11 and selection has to work there (R-20). - R-06 (state-driven): While the region's overview file is present, the app SHALL mount a second vector source over the same source layer, with the zoom range in Table B, drawing merged shapes, not individual fields, so the class colour stays readable at low zoom. For Brazil the response SHALL also carry `classProperty`, `mbmode24` or `class_id`, which is the single class source of the load (R-18); every load this block ships, the self-hosted extract and the source-direct mode alike, reports `mbmode24`. - R-16 (ubiquitous): The Brazil class table SHALL hold exactly the fourteen rows of Data contracts Table C1, whose class ids, English names and hex codes are read from the official Collection 11 legend CSV (`https://brasil.mapbiomas.org/wp-content/uploads/sites/3/2026/08/legend_code_mapbiomas_brazil_collection_11.csv`, 1,521 bytes, 33 data rows, sha256 `603239c5de7cca95799c788ab553a73ec3fc16477f681f63bb5af191d2f54dbe`, fetched on 2026-11-14, M-03). - R-17 (ubiquitous): The United States class table SHALL be generated from the official CDL raster attribute table (`https://pdi.scinet.usda.gov/image/rest/services/CDL_WM/ImageServer/rasterAttributeTable?f=json`, 38,504 bytes, 256 rows, sha256 `8b5cec2ff965a2d1f7f1205111b3a0fbe3cce5ed82cb0ef6a446ae304fe0b699`, fetched on 2026-11-14, M-21), and SHALL hold 255 rows, values 1 to 255, with the RAT's own `Class_Names` and its `Red`, `Green` and `Blue` converted to `#rrggbb`. ## Assumptions

- The CSB 2025 Feature Service answers the pilot box and holds real field geometry. Measured on 2026-11-14: 107 features for the box, `csbid 381825001868504` at 153.18667449 acres, eight CDL codes, 20,664 bytes for the attribute only query (M-20). Verified by AC-02 and AC-03 when the build lands.
- The county extract can meet the 250 KB detail budget at a zoom floor of 9 or lower. Not measured, because no extract exists; CO-B5-01 records `detail_minzoom`, and R-05 makes the build fail if it cannot. If `detail_minzoom` is 10, the default view at zoom 11 is below the interactive zoom and the build must be reworked; that is a build failure, not an app fallback.
- A fill at 0.4 keeps the imagery legible and the field edge visible. Not verified by anyone before this block; AC-11 measures the composited alpha and the basemap's own variation, and the value stays a named constant if the user prefers another number inside 0.35 to 0.5.
- The overview files meet the 300 KB cap with the coalesce recipe of R-10. Unverified for both regions, because no overview file exists yet; AC-06 measures each when the prerequisite cards produce one and fails the build if a tile exceeds the cap.
- MapLibre's overzoom of the detail tier keeps the polygons usable above its `maxzoom`. The geometry is the highest zoom generalisation, so edges are simplified at high zoom; this is accepted and not measured as a defect.
