AC-33 rectangles and stacking order, round 2 rework, branch block5/one-string-per-state

READING OF THE CRITERION. Revision 8 of the block 5 spec (commit 3a1fd85, the text in the tree after
the merge of `origin/main`) reads stacking "on the positioned element that carries each box's
`z index`, and never on a descendant of it", and it names the numbers: the map canvas 0
(`.map-panel`), the layer rail's anchor 20 "while the rail element inside it declares 25", and "the
region's own positioning wrapper is 25 (`polygonPanel` of `ZOrder`) while the `section` it holds reads
`auto`". The wrapper is the measured element and the upper bound is "the nearest mounted overlay above
the wrapper, named in the artifact with its own value", or "no upper neighbour is mounted" when none
is.

WHAT THE GATE MEASURED. Its FAIL row read `[data-polygon-region]`, the section, which computes `auto`
by design, and reported the region as not above the rail's 25. That reading is the one revision 8
excludes. Measured as revision 8 requires, the region's wrapper reads 25, above the map canvas (0) and
above the layer rail's anchor (20), so this criterion needed no code change. A first attempt on this
branch put a second `z-index: 25` on the section itself, which the criterion does not ask for and does
not read; that change is reverted in this commit and the tree carries no stacking edit for AC-33.

METHOD. Running app at http://localhost:5175/?region=us (backend on :8000), real browser, one page
load per width with CDP Emulation.setDeviceMetricsOverride 1440x900, 780x900 and 360x640.
`getBoundingClientRect` and `getComputedStyle().zIndex` read from the live DOM after the map settled.
An overlap is a positive-area intersection of the region's rectangle with each named box.

OVERLAP SCAN, 1440 and 780, positive area intersection with each mounted box

  The region intersects none of: the brand chip, the fields panel, the status notice (absent), the top
  right strip, the block 3 right edge column (absent at this state), the layer rail, the navigation
  control, the timeline dock. Two candidates reported a positive area and both are full-viewport
  wrappers, which the gate's P14 excludes (wrappers of 80 percent or more of the viewport):
  `.anchor-timeline-dock` (position fixed, inset 0, pointer-events none) at 60800 px2 at 1440 and
  26363.6 px2 at 780, the same box as `.map-canvas` under it. Neither is a box the region can
  intersect in the sense of R-41.
